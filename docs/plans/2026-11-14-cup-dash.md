# Cup Dash: build plan (2026-11-14)

> **Superseded for scope and steps 4+** by docs/plans/2026-11-14-cup-dash-courses.md (several themed
> courses, revised hole lengths, spec-baked holes, progression). Steps 1-3 below are done.

Source: docs/research/Cup Dash golf game design.md (+ notes). Branch: `cup-dash`. The game stays
`enabled = false` in games/golf/manifest.tres until step 10 passes.

## Decisions (from the research)
- **One custom deterministic solver** from strike to rest: RK4 flight, Penner-style bounce with a fixed per-surface
  tilt, Stimp-calibrated roll, analytic cup, tree hits. Pure GDScript in games/golf/logic/. No Jolt hand-off.
- **Real metres, short course:** physics stays at real scale (validated against launch-monitor data); the course is
  short by design - 9 executive-length holes, par 32 (4 x par 3, 4 x par 4, 1 x par 5), about 1.8-2.0 km.
- **Controls (portrait, one thumb):** pull back from the ball and release - pull distance = power, release timing =
  accuracy, an overpower band amplifies error, tap to cancel. Aim with a draggable landing marker. Spin behind a
  ball-icon panel. Putting: auto-scaled power range, moving-dot slope grid on greens, wind shown as drift.
- **Modes:** 9-hole stroke play, 3-hole match-play duel (fits the hub's best-of-3 pattern), closest-to-pin tiebreak.
  CPU shots skippable / 2-4x fast-forward.
- **CPU:** plans by expected strokes (strokes-gained table) over simulated candidates on a worker thread; Easy /
  Medium / Hard execute with high- / mid- / low-handicap error (Broadie). No rubber-banding. Target player win
  rates ~70 / 50 / 30 %.
- **Rendering:** Mobile renderer, MSAA 2x set once, render scale 0.75-0.8, one terrain shader (stripes, fringe),
  MultiMesh trees, blob shadow, strip-mesh trail, <= 100 draw calls.
